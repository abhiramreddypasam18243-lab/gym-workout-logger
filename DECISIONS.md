# Decisions Log

All decisions from the spec (section 18) plus project-specific choices made during build.

| ID | Date | Decision | Alternatives | Why |
| --- | --- | --- | --- | --- |
| D-01 | 2026-10-16 | A modular monolith | Microservices | Less operational complexity, same clean boundaries, easier to test and explain |
| D-02 | 2026-10-16 | React and TypeScript, FastAPI, PostgreSQL, SQLAlchemy 2 and Alembic, as the blueprint recommends | Other stacks | Typed end to end, relational constraints and transactions suit this data |
| D-03 | 2026-10-16 | Server-side revocable sessions in an `HttpOnly` cookie, with a CSRF token | Stateless JWTs | Logout and account deletion can truly revoke access, and cookies are not readable by scripts |
| D-04 | 2026-10-16 | Argon2id password hashing | bcrypt | Memory-hard, and current guidance favours it |
| D-05 | 2026-10-16 | Decimals travel as strings in the API | JSON numbers | No floating-point surprises in nutrient and load values |
| D-06 | 2026-10-16 | A deterministic greedy planner with an explicit scoring formula | Integer programming; ML | Reproducible, explainable and testable |
| D-07 | 2026-10-16 | Allergens are hard filters, unverified allergen data excluded by default | Treat unknown as safe | Catalogue data can be incomplete; wrong inclusion is worse than a smaller plan |
| D-08 | 2026-10-16 | Time and budget are hard caps only when user sets them; cuisine and variety only rank | Treat everything as ranking | Matches the blueprint's "filters" while keeping preferences flexible |
| D-09 | 2026-10-16 | Nutrient snapshots on plan and log items, catalogue version in each plan | Recompute from live catalogue | Later corrections never silently rewrite history |
| D-10 | 2026-10-16 | A foreign resource returns 404, same as a missing one | 403 | Does not reveal that the record exists |
| D-11 | 2026-10-16 | No weight-loss or deficit goals in v1; only `maintain` and `build_strength` | Include a cut goal | Strength-focused; deficit features carry more risk than this project can manage |
| D-12 | 2026-10-16 | Self-declared adult confirmation, plus birth-date check when given | Collect birth date from everyone | Collects less sensitive data; limitation documented |
| D-13 | 2026-10-16 | Cursor pagination | Offset pagination | Stable under inserts, no duplicates or gaps |
| D-14 | 2026-10-16 | Epley e1RM for 1 to 12 reps, with `e1RM = load` at 1 rep | Brzycki; any rep count | Simple, well known, rep range limits the error |
| D-15 | 2026-10-16 | `1 cup = 240 ml`, `1 tbsp = 15 ml`, `1 tsp = 5 ml`, no mass-volume conversion | Regional cup sizes; density tables | Predictable, avoids inventing densities |
| D-16 | 2026-10-16 | Credentials only over TLS beyond localhost, with mkcert private CA | Plain HTTP on the network | Passwords and sessions must not be readable on the network |
| D-17 | 2026-10-16 | Frontend API types generated from the OpenAPI document | Hand-written types | Front and back end cannot drift apart without CI failing |
| D-18 | 2026-10-16 | Neutral wording, hide-calories, pause, opt-in weight tracking | Always show everything | Reduces harm for users for whom numbers are unhelpful |
| D-19 | 2026-10-16 | A small reviewed catalogue with recorded sources and licences | Import a very large database | Quality, licence clarity and testability before scale |
| D-20 | 2026-10-16 | An automated layering check (domain imports nothing from frameworks) | Convention only | Keeps the rules pure and testable |
| D-21 | 2026-10-17 | Food data: USDA FoodData Central + Indian Food Composition Tables (IFCT/NIN) | USDA only | Broader coverage including Indian foods; both are government publications |
| D-22 | 2026-10-17 | Seed recipes cover 5 cuisines: Indian, Italian, Mexican, American, East Asian | 4 cuisines | More variety; spec requires at least 4 |
| D-23 | 2026-10-17 | Include optional Mifflin–St Jeor calorie estimate with full transparency | Manual targets only | Users benefit from a starting point; all inputs/assumptions shown |
| D-24 | 2026-10-17 | Default currency INR, default units kg; users can switch to lb | USD/lb | Project context is India-based |
| D-25 | 2026-10-17 | Open registration, toggleable via `REGISTRATION_ENABLED` env var | Invitation-only | Simplest for development; can be disabled for demo |
| D-26 | 2026-10-17 | TLS via mkcert private CA | Caddy auto-certs; manual OpenSSL | One command, well-documented, works on all platforms |
| D-27 | 2026-10-19 | New accounts start with "beef" in excluded ingredients (`DEFAULT_EXCLUDED_INGREDIENTS`); users can remove it | Remove beef from the catalogue; swap beef for chicken or mutton | India-focused app where many users avoid beef; keeps the catalogue intact and the choice with the user |
| D-28 | 2026-10-19 | Ten Indian budget recipes (≤ ₹50/serving, tag `budget_friendly`) built only from existing catalogue foods; prices are documented estimates | Add new foods (rajma, besan, soya, curd) from USDA | USDA FoodData Central was unreachable from the network; existing foods need no new nutrient data. New foods can follow once USDA is reachable. AC-51 recipe range widened from 15–25 to 15–40 |
| D-29 | 2026-10-20 | Add a `build_muscle` goal (+10% calories, *initial* placeholder); keep protein default 1.6 g/kg; still no weight-loss or deficit goal | Add a fat-loss goal (needs S6/D-11 changed); recomposition label for maintain | User asked for muscle building and weight loss; muscle building fits the safety rules, weight loss would require relaxing S6, which the user chose not to do |
| D-30 | 2026-10-20 | A daily budget is a strict cap: serving sizes are limited to those whose cost fits the slot's share, so no day exceeds the budget; substitutions obey the plan's budget and time caps | Budget as ranking only, letting servings scale to meet calories (₹150/day plans averaged ₹229/day) | User: "budget is important". Low budgets now fall short of calorie targets instead (₹150/day ≈ 2,340 of 2,800 kcal), flagged by existing target_deviation warnings |
| D-31 | 2026-10-21 | Allergy constraints and food tags use one set of 14 codes (`gluten`, `crustaceans`, `eggs`, `fish`, `peanuts`, `soy`, `milk`, `tree_nuts`, `celery`, `mustard`, `sesame`, `sulphites`, `lupin`, `molluscs`) in `app/domain/allergens.py`; the API maps old spellings (`soybeans`, `cereals_gluten`) and rejects unknown codes; a migration rewrites saved rows; seed foods must use the 14 codes | Rename the catalogue tags to the UI spellings | Review found the settings screen saved `soybeans`/`cereals_gluten` while foods were tagged `soy`/`gluten`, so those allergies never matched the exact-match filter (S9). Fixing at the API boundary also protects older clients |
| D-32 | 2026-10-21 | Custom-food editor (stretch): users add foods with per-100 g kcal, protein, carbohydrate, fat (and optional fibre) and EU-14 allergens; stored in `foods` with `owner_user_id`, labelled `User-entered`, `approximate`, allergens unverified; visible to and loggable by the owner only; never used by the planner; catalogue foods are read-only | Let custom foods into the planner; serving-based entry | User chose per-100 g entry for logging only. Keeps the planner on reviewed recipes (D-19) and invents no nutrient data |
| D-33 | 2026-10-21 | Progressive overload hint by double progression: when every working set at the last session's heaviest load reaches the top of the rep range (routine's, else 8–12), suggest one step more (+2.5 kg upper body, +5 kg lower body; +5/+10 lb), otherwise keep the load; never suggest less. Step sizes are *initial* placeholders in `config.py`. The e1RM chart also plots the heaviest working set per day | Percentage-based or RPE-based progression; auto-filling loads | Simple, explainable and testable; a suggestion the user accepts with one tap, not coaching advice |
| D-34 | 2026-10-21 | Weekly working-set targets per muscle group (`muscle_set_targets`, 1–40 sets), counted by the exercise's primary muscle for the current Monday-start week in the user's timezone; warm-ups excluded; included in export and deletion | Volume in kg per muscle; secondary muscles counted as half sets | Sets per muscle is the common way lifters plan volume and needs no extra exercise data |
| D-35 | 2026-10-28 | Diet tags imply each other: a vegan recipe also meets vegetarian, pescatarian and dairy-free, and a vegetarian one meets pescatarian; eggs are not vegetarian in this catalogue; the seed rejects a tag its ingredients contradict; the settings screen offers only tags some recipe carries (halal and kosher are not offered: no recipe is certified); oats carry `gluten` (EU Regulation 1169/2011 Annex II) | Tag every recipe with every implied tag by hand; treat eggs as vegetarian | Review found vegan breakfasts missing, pescatarian and halal plans always infeasible, an egg dish tagged vegetarian beside untagged egg dishes, and oats passing a gluten allergy (S9) |
| D-36 | 2026-10-28 | Avoided cuisines fill a slot only when no other candidate passes the hard filters, and then raise `cuisine_preference_unmet`; a recipe is not planned twice on one day while another candidate fits; removal counts are distinct recipes; plan-level notices are stored with the plan so a reload shows them | Avoid as a score penalty only; hard-filter avoided cuisines | AC-61 says avoided cuisines appear only when nothing else can fill the slot, and the −0.3 penalty let them win; still never infeasible because of cuisine (D-08) |
